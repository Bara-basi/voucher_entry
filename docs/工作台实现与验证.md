# 财务凭证工作台 · 实现与验证

更新日期：2026-10-20。

## 使用与部署

在 `second_step` 目录安装 `requirements.txt` 中的 Python 依赖，并执行：

```powershell
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run build
D:\python\python.exe scripts\serve_workbench.py --demo --port 8010
```

浏览器访问 `http://127.0.0.1:8010/`。演示模式使用已有飞书快照，数据库位于
`tmp/workbench-demo.sqlite3`，文件位于 `tmp/workbench-demo-exports/`。
演示模式不会回写飞书，映射变动也只进入演示数据库。

部门内网正式运行：

```powershell
D:\python\python.exe scripts\serve_workbench.py --host 0.0.0.0 --port 8000
```

使用 `.env` 中现有飞书配置；正式数据库为 `data/workbench.sqlite3`，导出文件为
`outputs/workbench/`。无登录，所有访问者具有同等权限，编辑历史按浏览器会话标识记录。
服务使用一个 Uvicorn worker，后台任务串行执行；SQLite 必须位于服务器本地磁盘。
停止服务后应一起备份数据库、导出目录和映射目录；不要把这些运行数据提交到公开仓库。

服务进程必须有正常的外网访问权限。若回写或重新拉取时出现
`WinError 10013`，说明服务是从受限执行环境启动的，页面本身仍可打开但所有飞书请求会失败；
应从普通终端或正式服务管理器重启，而不是继续尝试改飞书地址或 Token。

环境变量：

| 名称 | 用途 |
|---|---|
| `WORKBENCH_OFFLINE=1` | 演示模式；启动脚本 `--demo` 同时隔离数据库和导出目录 |
| `WORKBENCH_DB` | 自定义 SQLite 文件位置 |
| `WORKBENCH_OUTPUT` | 自定义导出目录 |
| `WORKBENCH_EXPECTED_APP_NAME` | 限定飞书应用名称；默认接受项目已知的两个名称 |

已只读核验当前配置：实际连接 **2026年  海关AI / 2026年报关数据**，并存在“汇率”表。
需求中的“2025海关 AI”也作为已知源名称保留。界面展示实际源名称，按配置的表 ID
连接并核验表名，不能任意切换到其他业务表。

## 交互与数据行为

- **范围**：外销（26MT）按报关单号分组，内销按 `合同号_1` 分组；可检索待开或按
  外销出口日期/内销出运日期检索。界面用“外销 / 内销”标签区分。已开、已导出、
  范围外记录混组或缺少业务单号会阻断生成。
- **编辑**：九列用友式凭证，直接编辑摘要、科目、辅助档案、币种、汇率、原币、数量和金额；
  可修改日期及制单人、增加/删除/排序分录。输入停顿 800ms 或失焦保存。
  修改金额即时更新合计，后台保存后重新校验；部分异常不会丢弃已构建分录。
- **来源补充**：原始飞书记录与本地覆盖分开保留。补充后必须重新计算；重新计算覆盖人工
  分录前要求明确确认，旧版本留存。再次检索发现来源变化时，不会静默覆盖已有草稿。
- **合同检索**：保留原文，索引支持 PI 前缀、Y、ADD、批次、工厂后缀及联合订单展开；
  歧义候选全部展示，不把检索归一化结果用于修改业务分组。
- **并发**：保存请求必须携带版本号。冲突时保留浏览器输入，提供服务器/本地版本比较；
  可采用服务器版本或明确确认覆盖。浏览器保留未提交输入，刷新可恢复。
- **映射**：客户、供应商沿用现有文件；产品初始显示 176 条有效同名存货映射，
  可新增、编辑、停用，并显示库存科目。保存至数据库后镜像更新原格式 JSON，
  产品镜像文件为 `mappings/product_alias_mappings.json`，首次正式保存时创建。
  用友主档保持只读。历史草稿标记映射版本过期，由财务重新计算。
- **导出**：先预览有效与排除清单，只导出后端校验通过且版本未变化的草稿。
  生成已验证的 53 列 `.xls`，支持不同制单日期及制单人；导出保存不可变快照。
  超出 `.xls` 行数限制时要求减少范围。
- **回写**：正式模式中文件持久化成功后，仅回写实际导出的源记录，且只更新
  `是否开凭证=已开`、`凭证开具日期=YYYY-MM`、`凭证开具结果=保存成功`。每 100 条保存检查点；
  失败可重试回写，不重新生成文件。重复下载无外部写入；旧导出存在更新版本时，
  禁止旧版本回写覆盖新版日期。已导出凭证再次编辑产生新修订，导出前提示替换旧文件。
- **恢复**：飞书源数据和汇率分页、凭证批量构建、导出、回写均保存任务状态。
  服务重启自动恢复未完成任务；失败任务可手动重试，请求标识防止重复提交。

### 飞书访问性能

- 工作线程复用飞书 HTTPS 连接，避免每个请求重新建立 TLS 连接
- `tenant_access_token` 在有效期内复用
- 飞书应用与表目录校验缓存 10 分钟
- 汇率快照缓存 6 小时，期间待开查询不再重复读取整张汇率表
- 待开模式仍只搜索待开记录及其所属合同/报关单，不扫描全表

在当前数据量下，真实待开查询从优化前约 32–72 秒降至首次约 3.4 秒、缓存命中后约 2.3 秒。

当前同时支持外销和内销。内销不生成暂估科目，采购进项统一使用正常进项税。
演示模式 `--demo` 不写回飞书；正式模式导出成功后自动更新上述三个状态字段。
凭证类别当前仅支持已验证的“记”。不修改其他飞书业务字段或用友主档。

### 动效

导航指示线与范围切换滑块平滑移动；页面采用轻微渐入，凭证翻页按方向短距离滑入。
按钮、凭证清单、问题卡片有轻微层次反馈；任务显示真实进度条或不确定进度指示，
保存成功有短暂确认。弹窗和提示条采用短时过渡。金额和编辑中的单元格不做跳动动画。
遵循 `prefers-reduced-motion`，系统减少动态效果时关闭非必要动画。

## 新接口

接口前缀 `/api`，JSON 请求；`X-Session-ID` 是浏览器生成的会话标识，不代表认证身份。
所有编码和分录字段使用字符串传输，保持前导零及十进制精度。

| 接口 | 用途 |
|---|---|
| `GET /meta`、`GET /catalogs` | 数据源、配置、日期、科目及档案 |
| `POST /tasks` | 创建 query / build / export / writeback 任务 |
| `GET /tasks`、`GET /tasks/{id}`、`POST /tasks/{id}/retry` | 进度及恢复 |
| `GET /snapshots/{id}` | 范围预览、完整分组、冲突与补入记录 |
| `GET /batches`、`GET /batches/{id}` | 共享历史批次及草稿恢复 |
| `GET /drafts/{id}`、`PATCH /drafts/{id}` | 读取与版本化自动保存 |
| `POST /drafts/{id}/recalculate` | 应用来源覆盖与最新映射重新计算 |
| `GET /mappings`、`PUT /mappings/{kind}` | 版本化维护映射 |
| `GET /history/{entity}` | 凭证或映射修改历史 |
| `POST /exports/preview` | 有效/排除清单与版本确认 |
| `GET /exports`、`GET /exports/{id}` | 文件记录及不可变凭证版本 |
| `GET /exports/{id}/download` | 下载已有 Excel |

`POST /tasks` 使用 `{kind, payload, request_id}`；同 kind/request_id 重试返回同任务，
相同标识携带不同参数会返回 409。凭证保存使用
`{version, header, rows, overrides}`。冲突返回 409，校验参数错误返回 422。
任务失败返回可读错误，可继续重试。

数据库存储批次、源快照、草稿、人工覆盖、问题、历史、映射、导出及任务检查点。
现有 `/vouchers` 接口不经过新草稿流程，保留原有行为；新网页全部使用 `/api`。

- 飞书待开范围使用记录搜索接口筛选 `是否开凭证=待开`，再按报关单补齐同组所有状态记录；附加订单单独检索基础合同作继承参考，不将基础订单加入待开范围。每一步分页独立持久化，可重试恢复。日期范围沿用完整读取。
