## 已验证的异常与边界

- 空范围、重复凭证、无效版本、过期版本和未知记录均返回明确错误。
- 同一凭证被两个窗口修改时，后保存请求返回 409，不覆盖先保存内容。
- 同一批记录被两个导出任务同时提交时，只允许一个成功。
- 同一报关单内混合已开、待开、空状态时进入人工核实提示；缺少业务单号仍硬阻断。
- 附加订单完整继承父单客户和供应商；联合订单不错误继承。
- 飞书分页失败后可从保存的页码检查点继续，不重复抓取已完成页。
- 飞书写回失败会保留 Excel 文件，并从已成功批次之后继续重试。
- 回写后的字段值会回读校验，接口返回成功但字段未落库时不标记成功。
- 手动异常标记、借贷不平衡、缺科目、缺档案、汇率非正数均阻止导出。

### 数据源界面核对

- 客户映射初始 20 条，运行时合并 30 条当前内销客户/别名，共 50 条且无重复别名；
  国内/国外分组缺失时按中英文字符数量推断，当前没有客户落入“未分组”。
- 辅助核算显示 47 个末级科目，根分类 15 个；`2001` 下 3 个末级项统一归入“短期借款”，
  `1408` 下 2 个末级项统一归入“委托加工物资”，父科目不再作为独立编辑项。
- 会计科目显示 351 个末级科目，根分类 66 个；原始 406 条中的 55 个父科目仅作为分类标题。
- 产品映射 176 条均能对应有效存货档案；缺失上级目录的末级存货按科目分类归组。
- 供应商映射 35 条均对应有效供应商档案。用友供应商快照本身没有分类字段，因此只显示一个列表。
- 科目、辅助核算沿用用友上级科目分组；汇率按年月和币种矩阵显示，人民币固定为 1，不单列。
- 人工选择“未分组”后会保持“未分组”，不再被档案默认分组覆盖；浏览器保存值已回读核对。

## 上线前必须确认

1. **访问控制**：`/api` 没有内置登录或角色权限。若使用 `--host 0.0.0.0`，
   必须放在可信内网，并由反向代理、VPN 或网络 ACL 限制访问；不要让普通办公网任意设备直接访问。
2. **单进程部署**：任务执行、飞书 Token 缓存和 SQLite 写入按单进程设计，必须保持
   `workers=1`。不要使用多个 Uvicorn/Gunicorn 工作进程。
3. **数据备份**：至少每日备份 `data/workbench.sqlite3` 和 `outputs/workbench/`。
   SQLite、导出文件和审计历史当前都没有自动备份与保留策略。
4. **重新启动**：本次修改包含后端代码，必须在维护窗口重新启动正式服务后才生效。
5. **真实环境抽查**：先在一个待开内销订单上完成查询、构建、导出和回写；
   再从飞书重新拉取，确认三个状态字段已落库。

2026-10-23 最终复核确认：Codex 执行环境启动的 Python 进程会继承受限网络令牌，
访问 `open.feishu.cn:443` 返回 `WinError 10013`；从该受限环境创建的独立 PowerShell
端口探测也无法连接。因此正式服务必须由普通 Windows PowerShell 或现有服务管理器启动，
不能从 Codex 会话内启动。

## 仍需关注的风险

| 级别 | 风险 | 建议 |
|---|---|---|
| 高 | 旧版 `/vouchers/generate*` 会绕过工作台的版本锁、审计和本地占用检查 | 仅在内网白名单开放；后续应统一停用，全部走 `/api` |
| 高 | 回写状态为 `done` 后若飞书字段被人为清空，系统不会自动发现 | 增加“重新核验回写”或定期对账任务 |
| 中 | 单任务队列串行执行，一个超大的导出会阻塞后续查询和构建 | 控制单次导出规模；必要时拆分独立任务队列 |
| 中 | 仓库仍跟踪 `vouchers/` 历史凭证和 `mappings/` 档案快照 | 确认仓库访问范围符合财务数据管理要求 |
| 中 | `.env` 含飞书和睿贝凭据，依赖服务器本地文件权限保护 | 仅授予运行账号读取权限，禁止打包或转发 |
| 低 | 长时间运行后 SQLite 审计历史会持续增长 | 制定 6–12 个月归档或清理策略 |
