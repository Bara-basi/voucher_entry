# 待确认规则

本文件登记"已发现、但尚未与财务确认"的规则。确认前，相关差异保留在核对底稿中，
但**不计入异常统计**，避免把口径问题误当成规则错误。

登记日期：2026-10-16

## 1. 暂估业务（应付账款_暂估 / 待抵扣进项税额）

**现状**：影刀旧版程序完全没有考虑这种情况（已与程序编写者确认）。目前生成规则
一律走正常科目，因此含暂估的凭证会对不上。

**已知事实（来自 98 个含暂估科目的分组）**：

- 金额、币种、数量、方向、辅助核算与正常处理**完全一致**，只有科目和摘要写法不同：
  - 进项税额行：`22210101 应交增值税_进项税额` → `22210107 应交增值税_待抵扣进项税额`
  - 应付行：`220201 应付账款_供应商` → `220202 应付账款_暂估`（出现 37 次，远少于 22210107 的 127 次，多数暂估单仍用 220201）
  - 摘要：采购段加前缀 `暂估-`，收入段加后缀 `-N月未开票收入`
- 把 22210107 / 220202 视作 22210101 / 220201 后，98 个分组中 84 个完全一致（不做替换时只有 37 个）。
- 存在"暂估 → 后期冲销"的配对（如 `26MT-08C024`：2026-03 贷 220202 57,522.12 暂估，
  2026-04 以负数冲销并冲回 140599）。
- **暂估会把一笔采购拆成两部分**：同一笔飞书记录的采购成本，一部分已取得发票按正常科目入账，
  另一部分按暂估入账。例如 `26MT-01T050C&080A&080-ADD1` 的第一条记录不含税成本 242,462.83，
  实际凭证里 106,852.21 走正常科目、135,610.62 走暂估（对应 220202）。
  因此不能只按"凭证摘要里有没有暂估两个字"来判定；核对时需要按合同整体归因。
- 时间分布高度集中：按出口月份 2026-08（26 组）、2026-09（40 组）；按凭证期间 2026-09（63 笔）。

**待确认问题**：

1. 什么条件下走暂估？（是否为"记账当时采购发票尚未到达"？）
2. 暂估时应付账款用 220201 还是 220202？两者并存，判断依据是什么？
3. 暂估冲销是否一律在下一个月，还是取得发票的当月？
4. 暂估凭证是否也需要由本工作台生成，还是仍由财务手工处理？

**现有字段不足以判定**：`开票情况=🚨未开票` 召回 61%、精确 81%；
`销项开票月` 含"当月未开票收入"且等于凭证期间 召回与精确均为 59.5%。
更关键的是，42 个暂估分组中有 15 组**现在已显示"已开票"**，说明这些字段记录的是
"当前状态"，而暂估与否取决于"记账当时的发票状态"，历史快照中无法反推。

**临时处理**：核对底稿中将该类差异标记为"待确认（暂估）"，不计入异常统计；
生成凭证时暂按正常科目处理，若后续财务确认触发条件，再补暂估分支。
