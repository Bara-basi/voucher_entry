# 凭证构建工作台

现已提供 Vue 3 + TypeScript 共享网页：凭证编辑、异常补充、自动保存、映射维护、批量导出与飞书回写。
新版界面使用 `/api` 接口；下文原有 `/vouchers` 接口继续兼容。
完整启动方式、接口、验证结果和新增文件清单见 [工作台实现与验证](docs/工作台实现与验证.md)。

```powershell
# 首次构建（在 second_step 目录）
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run build
# 本机演示：独立数据，不回写飞书
D:\python\python.exe scripts\serve_workbench.py --demo --port 8010
# 正式运行：读取配置的飞书源，导出后回写状态
D:\python\python.exe scripts\serve_workbench.py --host 0.0.0.0 --port 8000
```

从飞书多维表记录构建用友凭证导入模板，替代财务人员机械重复的录入工作。

当前范围：**合同号以 26MT 开头、销售方式 = 出口**。

## 目录结构

| 路径 | 说明 |
|---|---|
| `app/` | FastAPI 后端。`main.py` 路由，`services/voucher_service.py` 规则引擎 |
| `data/` | 运行时快照（飞书、用友导出），不入库 |
| `docs/` | 模板规则、映射方法、脚本说明、逻辑对齐、待确认事项 |
| `mappings/` | 用友档案快照、客户/供应商别名、飞书参考字典 |
| `outputs/` | 交付物：`single_voucher/`（单张凭证模板）、核对底稿 |
| `scripts/` | 飞书读取、用友只读抓取、客户匹配辅助 |
| `templates/` | 53 列导入模板（024 已验证格式） |
| `vouchers/` | 历史凭证快照（只读） |

### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 健康检查，返回数据快照文件是否存在 |
| GET | `/vouchers/groups` | 列出待生成的报关单号分组 |
| GET | `/vouchers/preview?customs_no=...` | 预览单个报关单号的凭证分录 |
| POST | `/vouchers/generate` | 全量生成，参数 `posting_date` / `contract_prefix` / `sale_method` / `output_dir` |
| GET | `/vouchers/pending` | 列出飞书中凭证状态为「待开」的记录 |
| POST | `/vouchers/generate-pending` | 读取「待开」记录，合并生成一个导入模板；`mark=true` 时回写状态 |
| POST | `/vouchers/generate-bulk` | 按出口日期范围批量生成一个导入模板，参数 `start_date` / `end_date` / `mark` |

生成结果默认写入 `outputs/single_voucher/`：一个报关单号一张凭证一个 `.xls`。
待开/批量接口输出到 `outputs/batch/`：一个文件内含多张凭证（凭证ID 递增）。

### 待开凭证流程

1. 从飞书实时读取 `是否开凭证 = 待开` 的记录（范围：26MT + 出口）；
2. 按报关单号构建凭证，全部合并进一个 `.xls`；
3. 生成成功的记录回写：`是否开凭证=已开`、`凭证开具日期=YYYY-MM`、`凭证开具结果=保存成功`；
4. 生成失败的记录只回写 `凭证开具结果`，内容为财务可读的简短原因（如"缺少供应商信息，请补全后重试"），不暴露内部异常信息。

`mark=false` 时只生成文件、不写回飞书，用于预览和核对。

## 生成口径

| 项目 | 规则 |
|---|---|
| 分组 | 按**报关单号**分组，一组一张凭证（与影刀程序一致） |
| 必填校验 | 报关品名/供应商/报关金额/合同号_1/销售方式/币种/不含税人民币收入/不含税成本/采购金额，任一为空整组跳过 |
| 收入区 | 应收(借) → 主营业务收入(贷) → 销项税额(贷，0 不出行) → 国际运费(负借方，0 不出行) → 保险费(负借方，0 不出行)；均取组内合计 |
| 采购区 | 库存商品(借) → 进项税额(借) → 应付账款(贷) → 主营业务成本(借) → 库存商品(贷)，按每条报关品名记录生成 |
| 科目 | 应收/收入按"销售方式 × 币种"；库存商品按用友存货档案编码前 4 位分类（0501 不锈钢 / 0502 镍合金 / 0505 钛 / 0506 钢 / 0508 附件 / 0599 其他…） |
| 存货档案 | 报关品名 → 用友存货档案同名叶子；同名多条优先取 05 开头编码；**档案中没有的品名直接报异常** |
| 出口退税 | 进项税额 = 0 且退税额 ≠ 0 时，进项税行改记"应交增值税_出口退税"，金额取退税额 |
| 摘要 | `{合同号}外销收入` / `{合同号}采购商品` / `{合同号}结转采购成本`；进项税、出口退税行加 `-专票`，销项税额行不加 |
| 汇率 | 海关AI「汇率」表（`tblYPyKNiJx3yOEC`），按**出口日期所在月份** |
| 金额 | 应收本币 = 报关金额 × 汇率；收入本币 = 不含税人民币收入；单价 = 不含税成本 ÷ 报关重量 |
| 平衡 | 应收本币由"不含税收入 + 销项税额 + \|运费\| + \|保费\|"倒算、应付行 = 不含税成本 + 税额（退税取退税额），保证账簿币借贷相等；倒算值与报关金额×汇率相差超过 1 元则报异常 |
| 汇率使用 | 除个别历史个例，财务 500 条外销收入应收行中仅 9 条使用非基准汇率，其中只有 26MT-07F015 是"手工调原币+自定义汇率凑平"（原币 811.28 vs 报关金额 810.61）；本工作台保持原币=报关金额、在本币侧吸收分位差，隐含汇率与基准仅差 0.000007 |
| 客户 | 买方英文名 → 客户名称_脚本用 → 已确认别名 → 历史解析 → 档案唯一匹配；仍无法匹配则报异常 |
| 附加订单 | 合同号以 `-ADD`/`空格ADD`/直接连写 `ADD`（含 `ADD1` 等）结尾且缺客户或供应商时，继承原始订单同名字段；`-A`/`-B` 是批次标记（如 `06H056ADD1-A`）、`Y` 是佣金标记（如 `07C210Y-ADD`），都属合法写法；含 `&` 的是联合订单，不参与继承 |
| 重复客户档案 | 同一客户存在多个编码且简称相同时，优先取凭证历史中使用次数最多的编码 |
| 供应商 | 供应商简称 → 别名表 → 供应商档案全名唯一匹配；**字段含多个名称直接报异常，不做拆分兼容** |
| 制单 | 制单人王益，制单日期与会计期间默认取生成日期 |

## 开发约定

- 全部文件 UTF-8。
- 临时脚本放 `tmp/`（已加入 `.gitignore`），确认无用后删除。
- 服务代码放 `app/services/`，特殊脚本放 `scripts/`。
- 缺数据、缺档案一律报异常，不猜测、不自动兼容。
